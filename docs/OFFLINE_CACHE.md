# 音频离线缓存（v0.17.0，方案与边界）

> 结论：**音频缓存可行，而且不需要改数据库/归档格式**。
> 这不是“把每首歌分别下载”，而是把「一张专辑 = 一个 B 站视频/分 P」的**整段 DASH 音频**缓存一次：
> 分曲只是同一音频流上的时间裁剪，所以缓存一次，离线时整张专辑所有分曲都能播放。

## 1. 为什么可行

- 播放模型已经是「专辑音频流 + `ClippingConfiguration` 切分曲」，不是每首歌一个独立文件；
- B 站 `playurl` 返回的是完整 DASH 音频流，下载一次即可；
- 缓存到应用私有目录后，播放 URL 失效/断网都不影响本地文件播放；
- 不需要改 Room schema、不需要改归档 v3（缓存是设备本地数据，不进入备份）。

## 2. 当前行为（v0.17.0）

入口：专辑详情 → 右上角更多 → **缓存整张专辑音频**。

- 下载当前音质档位的完整音频文件；
- 下载完成菜单变为「删除音频缓存（192K）」，可手动删除；
- 之后播放该专辑自动使用本地缓存，离线也能播放，不再消耗音频流量；
- 删除专辑时自动删除对应缓存；
- 缓存文件：`files/audio_cache/<bvid>_<cid>.m4a` + 同名 `.properties` 元数据；
- 下载失败/文件不完整会清理临时文件并提示；文件长度与 Content-Length 不一致视为失败。

## 3. 边界（刻意未做）

- **只缓存音频，不缓存歌词视频**：视频仍按需联网；
- **手动缓存**，不做“点播放就偷偷下载”，避免用户没决定就消耗流量；
- 没有后台下载服务/断点续传：目前离开专辑页会取消下载，失败需重试；
- 缓存固定为下载时的音质档位；之后改音质设置不会自动重下（菜单会显示缓存档位）；
- 缓存不进入归档/换机备份；清除 App 数据会一起删除；
- 不自动清理孤立缓存（删除专辑/手动删除已覆盖主要路径；后续可加缓存管理页）。

## 4. 实现位置

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 接口 | `data/repository/AudioCacheRepository.kt` | 查询/下载/删除缓存、缓存元数据 |
| 实现 | `data/impl/AudioCacheRepositoryImpl.kt` | 解析流 → OkHttp 下载 → 私有文件 + 元数据 |
| 播放 | `player/PlaybackEngine.kt` | `resolveStream()` 先查缓存；带 `file://` 时改用 `DefaultDataSource` |
| UI | `ui/album/AlbumDetailViewModel.kt` / `AlbumDetailScreen.kt` | 菜单入口、下载状态、删除、Snackbar |
| 容器 | `di/AppContainer.kt` | 注入 `audioCacheRepository` |

## 5. 后续可做（按优先级）

1. 缓存管理页（缓存总大小、逐专辑删除、清空全部）；
2. Wi-Fi-only 开关 + 后台/前台服务下载 + 断点续传；
3. 自动缓存当前播放的下一张专辑（需明确流量策略）；
4. 缓存过期/版本校验（音频地址失效时自动重下）；
5. 缓存命中时在专辑/曲目 UI 显示离线标记。
