## v0.59.3（2026-11-15 · tag `v0.59.3`）

**修复：从播放页收回迷你条时「不透明材质 → 毛玻璃」突变**

- 原因：过渡中曾强制迷你条用不透明底色（避免透出播放页残影），p 落到 0.1% 以下时切回
  Haze 毛玻璃，收起最后一刻材质突变；同时表面背景层只在 0~1% 内淡出，末端变化过于集中。
- 修复：**材质统一为毛玻璃**——展开/收起全过程迷你条始终是同一块 Haze 玻璃，不再切成不透明底；
  表面背景层淡入/淡出区间从 1% 放宽到 6%，收起末端是「表面卡片渐隐 + 玻璃逐渐透出页面内容」的
  渐变过渡（与椒盐音乐的渐变做法一致），不再是硬切换。
- 低版本/无 Haze 环境仍使用高不透明度 fallback 背景，行为不变。

验证：207 单测全绿；Debug/Release 构建成功；模拟器在 p=0.85/0.48/0.17/0.03 多档按住抽帧确认
材质全程一致、收起末端平滑过渡。
## v0.59.2（2026-11-15 · tag `v0.59.2`）

**修复：迷你条看起来像「外接矩形色块」、下方内容在胶囊上沿被裁断**

- 真正原因不是迷你条自己画了矩形：页面内容区（Page/RootTabPage）为迷你条预留了整条高度，
  内容在**胶囊上沿被裁出一条平线**，平线以下是页面背景色；胶囊玻璃与页面背景色接近，
  于是整个外接矩形看起来像一块浅色矩形，胶囊轮廓失去意义；被裁的标题/卡片也像被矩形遮挡。
- 修复：根 Tab 页面**内容改为从迷你条后面滚过去**（只预留底部导航高度），
  胶囊四角能透出下面的内容、玻璃能模糊背后内容；
  迷你条高度改由页面列表的 `contentPadding`（`LocalMiniPlayerContentInset`）保证，
  滚到底时最后一项仍会停在迷你条上方，不会被挡。
- 详情页与登录/导入/编辑等带底部表单按钮的页面保持原样（仍预留迷你条空间），避免按钮被悬浮条遮挡。

验证：207 单测全绿；Debug/Release 构建成功；模拟器验证发现页/音乐库列表可从迷你条后滚过、
胶囊四角透出卡片内容、滚到底最后一项仍完整可见。

## v0.59.1（2026-11-15 · tag `v0.59.1`）

**修复：从完全展开的播放页刚开始向下拖动时专辑封面「重影/发糊」**

- 原因 1（重影）：真实封面在 progress 94%→99.5% 之间与共享封面 overlay 交叉淡入，
  但两者位置/尺寸/圆角并不完全一致（播放页内容整体随 surface 平移，overlay 目标是页面内坐标），
  刚开始拖动就会看到两个位置不同的封面叠在一起。
- 原因 2（发糊）：overlay 封面的容器尺寸随拖动逐帧变化，Coil 按动画中的尺寸反复请求/解码，
  过渡中会停留在低清的迷你条封面位图上放大显示，看起来像重影/卡帧。
- 修复：
  1. 过渡中（0<p<1）**只由共享封面 overlay 绘制封面**，播放页真实封面只在完全展开（p≈1）时显示；
     p=1 时两者位置/尺寸/圆角完全一致，切换无感，不再有交叉淡入重影。
  2. `CoverImage` 新增可选固定解码尺寸 `requestSizePx`：overlay 封面按播放页真实封面目标像素
     解码（未量到目标时 1280，范围 720~1536），容器怎么变都保持同一张高清位图，不再发糊。

验证：207 单测全绿；Debug/Release 构建成功；模拟器 1080x1920 下按住拖动到 progress≈0.49/0.995
抽帧确认封面全程清晰、无重影；从播放页拖回迷你条全程连续。

## v0.59.0（2026-11-15 · tag `v0.59.0`）

**恢复上次播放会话；修复迷你条外接矩形露出表面背景色块**

### 1) 冷启动恢复上次播放会话（用户方向 A）

- 持久化最小会话状态（应用私有 SharedPreferences，轻量 JSON，5 秒节流，不进归档/备份）：
  专辑 id、曲目 id / startMs / index、曲内进度、播放模式（随机/循环）；
- 冷启动时静默重建队列并恢复为**暂停态**：迷你条直接显示上次曲目（封面/标题/艺术家），
  用户点播放即续播；**不在启动时解析音频流**，避免启动即请求网络；
- 首次播放/切歌/seek/跳队列时才真正 prepare 队列（`session RESUME` 日志）；
- 边界处理：专辑已删除/曲目被重新分割（按 id → startMs → index 兜底匹配）、
  进度停在结尾附近时回到开头、损坏 JSON 自动丢弃、播放过程中每 5 秒/暂停/切歌/播完保存；
- 迷你条显示规则保持不变（仅内容页显示；空态不常驻），避免遮挡登录/导入/编辑等页面底部控件。

### 2) 迷你条外接矩形露出表面背景色块（白边）

- 根因：`PlayerSurfaceLayer` 的表面背景层（surfaceContainer）在 p=0 时也绘制，且宽度用
  `LocalConfiguration.screenWidthDp`（整数 dp 取整）换算像素，比迷你条胶囊宽 1~2px；
  浅色主题下胶囊圆角外会露出一圈「白色矩形/色块」。
- 修复：使用真实窗口像素尺寸（`LocalWindowInfo.containerSize`）保证表面背景与胶囊严格对齐；
  并且 p=0（静止迷你条）时不再绘制表面背景——胶囊自身就是 Haze 玻璃，
  外接矩形保持透明；开始拖动后背景与迷你条内容同步淡入/淡出，展开行为不变。

验证：207 单测全绿（新增 3 个会话 JSON 兼容性测试）；Debug/Release 构建成功；
模拟器验证冷启动恢复（`session RESTORE album=1 track=2 pos=6262ms`）→ 点播放续播
（`session RESUME ... pos=6262ms` → `startQueue startPos=6262ms`）；静止迷你条圆角外无背景色块。

## v0.58.1（2026-11-15 · tag `v0.58.1`）

**修复：开始拖动迷你条时共享封面先消失/闪烁**

- 根因：共享封面 overlay 之前只在开始拖动/展开时才进入组合，此时 `CoverImage`（Coil AsyncImage）
  才发起加载，第一帧会先画 `surfaceVariant` 占位色方块；同时迷你条自己的封面按 `contentAlpha`
  快速淡出 → 视觉上「封面先消失，再出现一个新的取代」，中间闪一下。
- 修复：只要在播放且当前是封面页，overlay 就保持组合（透明度仍由共享进度控制），
  图片在开始拖动前已加载完成，跟手第一帧即连续；其余展开/收起/共享元素行为不变。

验证：204 单测全绿；Debug/Release 构建成功；模拟器 9:20 比例下以极慢起手拖动抽帧确认
封面从第一帧起连续、无占位色闪现；展开/收起/返回键回归通过。

## v0.58.0（2026-11-15 · tag `v0.58.0`）

**纯维测日志版本：补齐播放器表面/手势/后台/登录/设置等链路日志（无功能需求）**

本版不新增功能、不改 UI/交互，只提升「出问题时能从导出的诊断日志里自证现场」的能力。

### 诊断设施

- **维测日志默认开启**（`AppSettings.diagnosticLogsEnabled` / SharedPreferences 默认 true）：
  之前默认关闭，全新安装的用户反馈问题导出日志是空的，等于没有日志；老用户显式关闭过的保持关闭，
  设置页文案同步更新；

- 不记录 Cookie / 账号 / 二维码 key / 完整签名 URL 等敏感信息。

### 新增日志（tag）

  拖拽 START/STOP（速度/预测位置/判定规则）、迷你条 rect 变化、底栏高度、IME/mini inset、

- `Surface`：表面层进入/退出组合、mini 条进场/退场动画起止、播放页内容 `progress>=0.06` 组合/销毁、
  共享封面目标 rect 异常（非正方形/0 尺寸，v0.57 形变问题的回归探测器）、共享封面 overlay 显隐、

- `NowPlaying`：封面页↔歌词页切换、歌词页返回、播放列表面板开关、空态；
- `Play`（原 `PlaybackEngine` tag 统一为文档里的 `Play`）：播放/暂停/上/下一首/seek/跳队列/模式切换、
  准备失败、BUFFERING/READY/ENDED、`playWhenReady` 变化（音频焦点丢失/耳机拔出等）、错误重试；
- `Service`：后台播放服务 onCreate/会话建立/taskRemoved/onDestroy/拉起失败；
- `Auth`：启动登录态、refresh 结果与网络失败保留缓存、扫码阶段（WAITING/SCANNED/EXPIRED/SUCCESS）、

- `Stats`：听歌统计落库失败；`Theme`：封面取色种子变化与取色失败；
- `Api`：搜索 WBI 失败降级、降级失败、疑似风控（`all/v2` 无 video 分组）；
- `Resolver`：登录态变化导致媒体流缓存被清空。

## v0.57.0（2026-11-15 · tag `v0.57.0`）

**播放器表面三处根因修复：迷你条进场动画、共享封面形变、拖动后卡死**

- **点播放时迷你条突然弹出（无过渡）**：出现动画原来绑定在「PlayerSurfaceLayer 首次组合」上，
  但专辑页/根 Tab 路由上该层在开始播放前就一直处于组合中，`appear` 早已跑完；
  且 `rect` 未测量时 early-return 分支与主分支各渲染一个 `MiniPlayerBar` 实例，测到 rect 后
  切换实例会打断 `AnimatedVisibility` 的进场动画。改为按「当前是否有曲目」驱动进场/退场
  （280ms/220ms），迷你条只保留单一稳定调用点，surface 卡片与迷你条一起淡入/上移；
- **慢速拖动时共享封面被拉成长方形**：播放页封面用 `boundsInWindow()` 测量，默认
  `clipBounds = true` 会把超出窗口的 bounds 裁到窗口边缘；展开早期真实封面还在窗口下方，
  量到的是 896×4.1 / 896×508 之类的「动态扁矩形」，overlay 按错误目标独立插值宽高 →
  封面变成长方形（p≈0.22 时最差约 1.75:1）。改用 `boundsInWindow(clipBounds = false)`
  后目标恒为正方形，全程宽高比 1:1；
- **拖动后迷你条「完全卡住」**（半展开卡片 + 迷你条半透明，progress 冻在 ≈0.059）：
  向下拖动时播放页内容（含顶部下拉热区 = 唯一下拉手势节点）按 `progress >= 0.06` 条件组合，
  手势进行中跨过 0.06 时节点被 dispose，draggable 在 detach 状态下丢弃 `onDragStopped`，
  没有 spring 收敛。把热区从播放页内容中提出来常驻组合（跟随 surface 平移、收起态移到屏幕外），
  手势节点不再在拖动中途销毁；另加「曲目清空」时的收敛兜底，避免半展开表面残留；
- 顺带修复 surface 背景比迷你条宽 12dp 的「翅膀」：p=0 时 surface 左右边界按迷你条内边距内缩，
  展开过程中平滑过渡到全屏宽；删除 v0.55 遗留的标题/艺术家/播放按钮测量死代码。

验证：204 单测全绿；Debug/Release 构建成功；模拟器慢放（animator duration scale 10）确认
进场动画逐帧淡入 + 上移（`docs/screenshots/v057_mini_enter.png`）；慢速拖动抽帧确认共享封面
全程正方形、p=0 表面与迷你条等宽（`docs/screenshots/v057_drag_cover.png`）；

**播放进度条改为成熟「实时频谱 seekbar」+ 音量条完美隐藏/贴边点按显形**

### 1. 进度条：实时频谱 + 染色圆点（参考成熟波形 seekbar 方案）

- 调研结论：成熟音乐 App 的进度条基本是两类——

- 本版采用 **live-spectrum 模式** 的自绘实现（不新增依赖）：

  - **拖动 seek 时振幅压缩到 30%**（`spectrumCompression`），避免跳动影响定位手感；
  - 点击/拖动定位、进度语义、无障碍保持不变。
