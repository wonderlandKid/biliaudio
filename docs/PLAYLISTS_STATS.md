# 歌单与听歌统计（v0.21.0）

## 1. 信息架构

- **音乐库**：保持“纯搜索音乐库”，只负责歌曲/专辑/艺术家的浏览与检索；
- **发现**：所有“和听歌行为有关”的入口集中在这里，用四个只露前 4 条的区块：
  - 「随机专辑」：4 张随机抽样 + 换一批/导入；
  - 「我的歌单」：4 个歌单预览，查看全部进入歌单列表；
  - 「听歌统计」：Top4 专辑时长，查看全部进入统计页；
  - 「最近播放」：4 张预览，查看全部进入最近播放详情（最多 10 张）；
- **设置**：缓存管理、诊断等设备维护项（缓存不属于听歌行为）。

发现页不重复放搜索栏（搜索统一在音乐库）。

## 2. 歌单

### 数据模型（Room v4）

| 表 | 用途 |
| --- | --- |
| `playlists` | 歌单 id / 名称 / createdAt / updatedAt |
| `playlist_entries` | 歌单条目：playlistId + **trackUid** + albumId + position |

- 用 **trackUid**（跨重导入/重编辑稳定）而不是自增 trackId 引用歌曲；
- `(playlistId, trackUid)` 唯一，重复添加会被忽略；
- playlistId 外键级联删除；albumId 外键级联删除（删专辑时清理歌单条目）；
- 追加歌曲时 position 递增；删除后允许空位。

### 页面

- 发现 → 我的歌单：
  - 列表：歌单名 + 歌曲数；右上角新建；
  - 空态引导新建；
- 歌单详情：
  - 名称、歌曲数、播放全部、添加歌曲；
  - 歌曲列表支持点播、单曲移除；
  - 更多菜单：重命名、删除歌单（不会删除音乐库歌曲）；
  - 添加歌曲底部 Sheet：搜索 + 多选 + 勾选已在歌单中的歌曲；确认后批量追加。

## 3. 听歌统计

### 数据模型

`track_stats` 按 **trackUid** 持久化：

| 字段 | 含义 |
| --- | --- |
| trackUid | 稳定歌曲 ID（未分割专辑使用 `album:<id>` 虚拟 uid） |
| albumId | 专辑（外键级联，删专辑清统计） |
| playCount | 开始播放次数 |
| listenedMs | 实际收听时长（毫秒） |
| lastPlayedAt | 最近播放时间 |

### 记录规则

- **播放次数**：歌曲开始播放（入队/切歌）时 +1；重复播放（REPEAT）当前不额外计数；
- **收听时长**：播放器 `isPlaying` 时按真实经过时间累计；
  - 每 ~5 秒批量写库；
  - 暂停 / 切歌 / 重新入队时 flush，避免丢失；
  - 单次 tick 最大按 1 秒计入，防止后台冻结后一次补入大量时间；
- 专辑时长 = 该专辑所有 track_stats.listenedMs 求和；
- 未分割专辑的虚拟整张曲目也计入；统计页会显示为一条“整张专辑”。

### 页面

发现 → 听歌统计：

- 顶部累计收听时长 + 累计播放次数；
- Tab 1「专辑时长」：按专辑累计收听时长排行，显示封面/名称/艺术家/时长条；
- Tab 2「歌曲次数」：按播放次数排行，显示歌曲/专辑/次数/累计时长；
- 空态说明播放后才有数据。

## 4. 持久化与独立备份（v0.22.0）

- 歌单/统计本身持久化在 **Room v4**（playlists / playlist_entries / track_stats），正常退出/重启不丢；
- 与音乐库归档**分开导出**：设置 → **用户数据** →「歌单与听歌统计备份」；
  - 独立 JSON：`biliaudio-user-data-*.json`，不包含专辑/分曲/封面/缓存；
  - 导出条目用 `(source,bvid,page) + startMs` 定位，换机/恢复音乐库后仍能重新关联歌曲；
  - 恢复时按名称合并已有歌单，统计按 `max(playCount, listenedMs)` 合并，避免重复导入导致翻倍；
  - 音乐库归档（Archive v3 bundle）不包含歌单/统计；归档中的 playlists.json 仍只是预留 schema。

## 5. 已知边界

- 歌单/统计**不进入音乐库归档**，只通过上面的独立用户数据 JSON 备份；
- 没有拖拽排序、歌单封面、歌单分享；
- 统计排行只展示前 50 张专辑 / 前 100 首歌；
- 重复播放的计数规则以“开始播放”为准，不是“每听完一首才算”；
- 重编辑分曲后，旧 UID 的统计可能成为孤立记录（不显示，但不会崩溃）；后续可清理。
