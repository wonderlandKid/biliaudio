# 批量导入格式规范（v1，数据层解析器与导入页文案共用）

> **注意**：v0.2.0 起推荐使用统一的「音乐库归档格式」（docs/LIBRARY_ARCHIVE.md），
> 一个文件同时承载专辑、分曲与备份；本文件定义的 JSON 数组 / CSV / 文本块仍然兼容，
> 作为「快捷导入 / 旧格式」继续支持，解析结果会统一归一化为归档模型后入库。


导入接口：`AlbumRepository.importBatchText(text: String): BatchImportReport`
解析器：`data/impl/BatchImportParser`（data teammate 实现，本文件是唯一格式依据）

## 自动识别规则

按顺序尝试：JSON 数组 → CSV → 文本块。全部失败时，每行按「无分曲的单专辑」再尝试一次。

## 格式 A：JSON 数组

```json
[
  {
    "bvid": "BV1GJ411x7h7",
    "title": "专辑名（可选，默认视频标题）",
    "artist": "艺术家（可选，默认 UP 主）",
    "mode": "single",
    "segments": [
      { "start": "00:00", "name": "曲目一" },
      { "start": "03:21", "name": "曲目二" },
      { "start": "07:45.500", "name": "曲目三" }
    ]
  }
]
```

- `mode`：`"single"`（默认，整段视频手动分曲）。`"multipage"`（按分 P 自动生成曲目）**当前版本尚未支持**，解析器可识别但导入会返回中文 Failure「多 P 视频暂不支持自动分 P 导入」，后续版本实现。
- `segments` 可省略/为空 → 整段视频作为一首歌。
- `start` 支持 `秒数`、`mm:ss`、`mm:ss.SSS`、`hh:mm:ss`。
- 也接受 `"url"`（B 站视频链接）代替 `"bvid"`。

## 格式 B：CSV（每行一首歌，同一 BV 的多行自动合并为一张专辑）

```csv
BV1GJ411x7h7,专辑名,艺术家,00:00,曲目一
BV1GJ411x7h7,专辑名,艺术家,03:21,曲目二
```

- 字段固定 5 列：`BV号,专辑名,艺术家,时间点,歌名`
- 艺术家与专辑名可留空（写 `,,`）；时间点必填；歌名可留空则自动命名 `曲目 N`。
- 支持带表头（首行含 `bvid` / `BV` 等关键字时跳过）。

## 格式 C：文本块（适合直接粘贴评论区分割点）

```text
BV1GJ411x7h7 专辑名
  00:00 曲目一
  03:21 曲目二
  07:45 曲目三

BV1uv411q7Mv 另一张专辑
  00:00 第一首
```

- 以 `BV`/`av`/`http` 开头的非缩进行开始一张新专辑；同一行后面可跟专辑名（可空）。
- 其后缩进行（以空白开头）为分曲：`时间点 歌名`。
- 专辑块之间用空行分隔。

## 行为约定

- 已存在同 `bvid` 的专辑：MVP 默认覆盖更新（保留原专辑 id 与播放次数，替换元信息和分曲），并在 `ImportResult.Success` 返回该 id。若 data 层选择“跳过重复”，需在汇报中说明，由 Lead 同步 UI 文案。
- 单条失败不影响其他条目；返回 `ImportResult.Failure(input, message)`，message 用中文且可在 UI 直接展示（如「视频不存在或已失效」「BV 号格式不正确」「获取播放信息失败」）。
- 导入时网络请求串行 + 间隔 ≥300ms，避免风控。
